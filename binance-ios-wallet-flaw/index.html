Binance iOS Wallet Flaw (worse_query): What Happened, Who Is Affected, and How to Check Your iPhone

By Crypto Desk.

On 10 November 2026, Binance warned users about a vulnerability in Apple's iOS 26.7.1, 27.0.1 and 27.2 that could let a third-party app read private files stored by other apps — including crypto seed phrases, private keys and login credentials. The flaw, publicly disclosed as "worse_query", is an iOS sandbox escape: a malicious (or innocent-looking, sideloaded) app can browse, export, edit and delete other apps' data without a jailbreak. No cryptocurrency losses have been confirmed as of this writing, and Apple shipped security updates on 9 November — but whether those notes fully cover this issue is still unclear. This page is the event timeline, the impact analysis, and a step-by-step self-check for your own iPhone.

What happened (timeline)

DateEvent
~8 Nov 2026Researcher forcequitOS publishes the PoC exploit code "worse_query" on GitHub — a "direct successor to bad_query" that reads other apps' containers via an App Group container; he notes the code is "intended for developers" and says he's giving up the Apple bounty after Apple stalled on responding.
9 Nov 2026Apple releases iOS security updates: iOS 27.2.1, iOS 26.7.3 and iOS 18.7.12, addressing nine flaws per BleepingComputer. One fixed vulnerability, CVE-2026-113963 (reported by László Várady, via App Intents), lets an app access sensitive user data — it is not yet confirmed whether this is the same issue Binance warned about. A file-manager app built on worse_query, WQ Files (by Christoph Kolbicz), is confirmed working on iOS 26.7.1, 27.0.1 and 27.2 via sideloading (AltStore/SideStore).
10 Nov 2026Binance issues its warning (quoted in full below). BleepingComputer and other outlets report; Hacker News picks it up.
10–11 Nov 2026Security Affairs analysis: "No attacks are reported and no fix is confirmed" in Apple's release notes for the specific issue; Binance and the researcher report no attacks or data theft so far.

What Binance said (verbatim, 2026-11-10)

"A vulnerability (worse_query) affecting iOS 26.7.1, 27.0.1, and 27.2 allows malicious apps to read local files from other apps, putting seed phrases, private keys, and login credentials at risk across the entire ecosystem. This is an iOS-level issue, not unique to Binance."

Binance's recommendations: install the update immediately as a precaution; delete unnecessary and untrusted apps; apply the latest versions for iOS and all apps; where compromise is suspected, transfer funds to a new wallet created on a clean device and reset all active login sessions.

Dual-source check: the affected iOS versions (26.7.1 / 27.0.1 / 27.2), the PoC name (worse_query), the WQ Files app, the "no confirmed losses" status and the Apple 9 Nov update are independently reported by BleepingComputer (10 Nov) and Security Affairs (10–11 Nov), quoting Binance's own statement and the researcher's GitHub — ✅ sources agree on every load-bearing fact.

Who is actually affected

All four conditions must be true:

  1. iPhone on iOS 26.7.1, 27.0.1 or 27.2 (the confirmed-affected versions).
  2. A crypto app with secrets stored on-device — the Binance app, any self-custody wallet (Ledger Live, Trust, Exodus, MetaMask iOS…), a 2FA app holding seed-related data.
  3. A second app with file access capability — classically a sideloaded app (AltStore, SideStore, TestFlight builds, enterprise-certs) like WQ Files, or an untrusted app that created/uses an App Group container. (Apps from the curated App Store are the harder path, but the flaw is an iOS-level sandbox escape, so "I only use the App Store" is not a full defense.)
  4. That second app ran while the flaw was exploitable.

If you're on a different iOS version (including the patched 27.2.1 / 26.7.3 / 18.7.12), you're outside the confirmed set. If you never sideload anything and run a current iOS, your practical risk is low — but the fix cost is minutes, so do it anyway.

Self-check: 5 steps for your iPhone

  1. Check your iOS version. Settings → General → About → Software Version.
  2. 26.7.1, 27.0.1 or 27.2 → you're in the affected set; continue.
  3. 27.2.1, 26.7.3, 18.7.12 (or anything newer) → patched; still do step 3.
  4. Update iOS immediately if you're on an affected version: Settings → General → Software Update → Download and Install. (Note: Apple's release notes don't explicitly name worse_query, so treat "updated" as necessary-but-verify.)
  5. Audit installed apps. Settings → General → iPhone Storage: look for apps you don't recognize, and specifically anything installed via AltStore / SideStore / TestFlight in the last few weeks. Delete the unnecessary and untrusted ones (per Binance's guidance).
  6. In the Binance app (or any crypto app): Settings → Security / Accounts → reset active login sessions (device management), and review recent withdrawals and withdrawals requests in your activity log for anything you don't recognize.
  7. If you suspect compromise, rotate like you mean it:
  8. Create a new wallet on a clean device (a phone that never had the suspicious app).
  9. Move funds from the old wallet to the new one.
  10. For the Binance account: log in on the clean device, enable/verify 2FA, reset active sessions, and consider withdrawing to self-custody if the balance is meaningful.
  11. Do not reuse the old recovery seed/keys after a suspected read.

Fix status (as of 2026-11-11)

  • Apple: updates shipped 9 Nov (27.2.1 / 26.7.3 / 18.7.12); the specific worse_query fix is not yet explicitly named in the release notes — unconfirmed, watch for clarification.
  • Binance: no confirmed losses; guidance = update + delete untrusted apps + rotate on suspicion.
  • Researcher (forcequitOS): PoC public on GitHub; code "isn't useful by itself" but WQ Files already packages it; no attacks reported.
  • Bottom line: the exploit is public, the versions are known, the patch exists but the coverage is unconfirmed — the 24–72h window after a public PoC is when opportunistic abuse usually appears. The self-check above is cheap; do it now, not next week.
